# Mission Control: observable multi-agent business research (v2)

Mission Control is a **local, passive observability prototype**, not an alternate agent runner. It receives actual Claude Code/Codex lifecycle events and displays the statuses and short metadata fields it really observed. It does not create parallel agents, verify citation truth, claim that a task was completed unless a completion event arrived, or calculate fake percentages or spend.

## One-time setup (macOS/Linux; Python 3.10+; no packages)

```bash
# Run these from the extracted bundle:
python3 install.py --platform both --scope project --project /path/to/my-repo --force
python3 configure_hooks.py install --platform both --project /path/to/my-repo

# Start a run for the repo (do this before invoking the skill):
python3 /path/to/my-repo/.agents/skills/greenfield-business-evaluator/scripts/gf_observe.py start \
    --project /path/to/my-repo --idea "My greenfield business idea"

# Start the local dashboard (separate terminal; run on your own computer):
python3 /path/to/my-repo/.agents/skills/greenfield-business-evaluator/scripts/gf_observe.py serve \
    --project /path/to/my-repo --port 8765
```

Open **http://127.0.0.1:8765** in your own browser. Invoke `$greenfield-business-evaluator ...` in Codex or `/greenfield-business-evaluator ...` in Claude Code in this repo. The dashboard automatically refreshes about every 1.5 seconds.

**Mac mini shortcut:** make your repo path current and use `python3 .agents/skills/greenfield-business-evaluator/scripts/gf_observe.py ...` for the Codex-installed shared script. The same script is also under `.claude/skills/...`.

Restart the coding assistant after setting up hooks. Open `/hooks` in Codex and trust the new hook definitions; Claude may ask you to trust project hooks. If the host disables hooks or uses cloud execution without local hooks, there is no live lifecycle feed. Hook installation does **not** enable browsing or parallel delegation.

## Alternative Codex CLI telemetry

Codex's documented `codex exec --json` emits JSONL you can pipe into the adapter:

```bash
codex exec --json "$greenfield-business-evaluator Evaluate a business idea..." \
  | python3 .agents/skills/greenfield-business-evaluator/scripts/gf_observe.py ingest-codex --project .
```

Run `start` before this pipeline. The adapter stores event names/tool categories and reported token usage (when present), *not* commands, prompts, reasoning, or full messages. CLI stream entries without an explicit recognized specialist identity are labeled **orchestrator**. Use trusted local lifecycle hooks for richer native specialist attribution. This pipe is one-shot; preserve Codex's exit code separately if your shell pipeline needs accurate failure detection (`set -o pipefail`).

## Manual checkpoints (optional)

The skill orchestrator can emit honest meta-events when a research source or final artifact has genuinely been recorded:

```bash
python3 .agents/skills/greenfield-business-evaluator/scripts/gf_observe.py emit --project . \
  --event source_seen --agent gf-market --url https://www.census.gov/ --message "Original market denominator captured"

python3 .agents/skills/greenfield-business-evaluator/scripts/gf_observe.py emit --project . \
  --event artifact_created --message "DECISION.md written"
```

Do not emit `agent_started`/`agent_completed` unless an actual agent started/completed. Never fabricate activity. The dashboard displays distinct badges for real vs. `demo` runs.

## Data and permissions

- The server **only binds to `127.0.0.1`** and exposes read-only GET endpoints. It has no agent execution, mutation or internet API.
- Data resides in `<repo>/.greenfield-observe/runs/<run-id>/events.jsonl` and meta.json. The only active-run marker is `.greenfield-observe/active.json`.
- Hooks observe only `gf-*`/`gf_*` specialist names. They do **not** store tool inputs, source page contents, agent text, prompts, intermediate reasoning, secrets, file contents, or exception messages.
- CLI usage metrics are populated only when reported by Codex `turn.completed`; no cost is guessed. Claude Code token/cost telemetry is not integrated yet; its native OpenTelemetry export could be added later.
- A `source_seen` event indicates **a recorded source**, **not verified accuracy**. Source URLs (when manually supplied) have query strings/fragments removed, and local/private-address URLs are rejected.
- An agent that stops sending activity is marked `quiet` after five minutes, **not failed**. `queued` means a defined role that has **not been observed starting**, not that work is actually scheduled.
- This prototype stores short labels and sanitized paths; even metadata may reveal business research. Add `.greenfield-observe/` to `.gitignore` if the idea is private. Secure your local machine and repository accordingly. Don't expose port 8765 through a proxy or tunnel.
- The hook installer modifies only project-local hook configuration after opt-in: `.claude/settings.local.json` and `.codex/hooks.json`. Existing unrelated hooks are preserved. To revert:

```bash
python3 configure_hooks.py remove --platform both --project /path/to/my-repo
```

## v2 complete: task checkpoint tracking, evidence coverage, approximate costs

The prior dashboard displayed actual subagent lifecycle hooks. The complete release adds an **independent persistent task manifest**: `task-manifest.json` in the active run folder. Task claims/checkpoints are explicitly emitted by the research orchestrator; they are not proof that native lifecycle hooks fired.

```bash
SKILL=.agents/skills/greenfield-business-evaluator
python3 "$SKILL/scripts/gf_runs.py" --project . plan
python3 "$SKILL/scripts/gf_runs.py" --project . claim --role gf-market
# Only after a genuine market research result has been saved to disk:
python3 "$SKILL/scripts/gf_runs.py" --project . complete --role gf-market --artifact research/greenfield/example/specialists/gf-market.md
# Restart interrupted runs without redoing checksum-valid fresh reports:
python3 "$SKILL/scripts/gf_runs.py" --project . resume --freshness-hours 72
python3 "$SKILL/scripts/gf_runs.py" --project . coverage --evaluation research/greenfield/example/evaluation.json --verification-report research/greenfield/example/source-verification.json
python3 "$SKILL/scripts/gf_runs.py" --project . status --usd-per-million-tokens 5
```

The dashboard now displays real task checkpoints and claim coverage next to observed lifecycle activity. Its claim counts are derived from saved evaluation/verification files, not from invented agent progress. The token-cost calculation is an **optional estimate** from actually reported tokens and a user-specified blended rate; it is not an invoice or precise per-agent billing. See [v2 workflows](skill/references/v2-workflows.md).

To show a **qualified cost estimate on Mission Control**, explicitly supply your own blended USD per million reported tokens and then refresh the dashboard:

```bash
python3 "$SKILL/scripts/gf_runs.py" --project . set-rate --usd-per-million-tokens 5
```

This is not a live price lookup or provider bill: unused/unreported tokens and differing input/output models are not captured. Without both a rate and reported usage, the dashboard displays `Unknown`.
